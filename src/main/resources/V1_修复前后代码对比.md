## 问题1：高点击无转化时投放入口未处理

### 修复前（❌ 错误）
```java
// 判断条件
boolean condition1 = adGroup.getClicks() >= 20 && spends > 5 && !hasOrders;
boolean condition2 = adGroup.getClicks() >= 20 && cpa >= 5;
boolean shouldProcess = !condition1 && !condition2;

if (!shouldProcess) {
    return;  // ❌ 直接返回，投放入口未处理！
}

// 下面的投放入口处理代码永远不会执行
// ...
```

**问题**：满足高点击无转化条件时，直接返回，导致投放入口完全未处理，不符合策略要求。

---

### 修复后（✅ 正确）
```java
// 【修复问题2】判断广告组是否满足"高点击无转化"条件
boolean condition1 = adGroup.getClicks() >= 20 && spends > 5 && !hasOrders;
boolean condition2 = adGroup.getClicks() >= 20 && cpa > 5; // ✅ 修正：>= 改为 >

// 【修复问题1】标记是否为"高点击无转化"情况，但继续处理投放入口
boolean isHighClickNoConversion = condition1 || condition2;

// ✅ 继续处理投放入口，不再直接返回
// 查询投放入口...

// 投放入口无订单时的处理
if (placementClicks >= 4) {
    // ✅ 根据标记使用不同公式
    double offset = isHighClickNoConversion ? 0.02 : 0.04;
    double targetBid = placementCpc + offset - 0.01 * placementClicks;
} else if (placementClicks > 0) {
    // ✅ 根据标记使用不同公式
    double targetBid = isHighClickNoConversion ? (placementCpc - 0.02) : placementCpc;
}
```

**效果**：
- ✅ 高点击无转化时投放入口仍会被处理
- ✅ 根据情况使用不同的Bid计算公式
- ✅ 符合策略文档要求

## 问题2 & 问题4：CPA边界值 & Bid舍入方式

### 修复前（❌ 错误）
```java
// ❌ 问题2：CPA判断使用 >= 而不是 >
boolean condition2 = adGroup.getClicks() >= 20 && cpa >= 5;

// 有订单时的Bid计算
if (placementAcos > acosControlBase) {
    double targetBid = (acosControlBase * placementCpc / placementAcos) - 0.01;
    // ❌ 问题4：使用四舍五入而不是向上取整
    BigDecimal bd = new BigDecimal(targetBid);
    targetBid = bd.setScale(2, RoundingMode.HALF_UP).doubleValue();
}
```

**问题**：
- CPA=5.0时会触发高点击无转化判断（策略要求>5才触发）
- Bid计算0.234会得到0.23（策略要求向上取整为0.24）

---

### 修复后（✅ 正确）
```java
// ✅ 问题2修复：改为 >
boolean condition2 = adGroup.getClicks() >= 20 && cpa > 5;

// 有订单时的Bid计算
if (placementAcos > acosControlBase) {
    double targetBid = (acosControlBase * placementCpc / placementAcos) - 0.01;
    // ✅ 问题4修复：向上取整
    BigDecimal bd = new BigDecimal(targetBid);
    targetBid = bd.setScale(2, RoundingMode.UP).doubleValue();
}
```

**效果**：
- ✅ CPA边界值判断与策略文档一致
- ✅ Bid计算使用向上取整，更保守的出价策略

## 实际案例对比

### 案例1：高点击无转化广告组

**场景**：
- 广告组点击数：25
- 花费：6欧
- 订单数：0
- 投放入口点击：8

**修复前结果**：
```
❌ 判断：满足高点击无转化 → 直接返回
❌ 投放入口处理：跳过（未处理）
❌ 结果：该投放入口继续浪费广告费
```

**修复后结果**：
```
✅ 判断：满足高点击无转化 → 继续处理投放入口
✅ 投放入口处理：使用公式 CPC + 0.02 - 0.01 × 8
✅ 目标Bid：假设CPC=0.5，则目标Bid = 0.5 + 0.02 - 0.08 = 0.44
✅ 结果：降低Bid，控制垃圾流量
```

---

### 案例2：ACOS Bid计算

**场景**：
- 投放入口ACOS：50%
- 投放入口CPC：0.50
- ACOS控制基准：35%

**计算过程**：
```
目标Bid = (35% × 0.50 / 50%) - 0.01
        = (0.35 × 0.50 / 0.50) - 0.01
        = 0.35 - 0.01
        = 0.34
```

**修复前结果**：
```
❌ 使用 RoundingMode.HALF_UP
❌ 如果是0.344 → 0.34（正确）
❌ 如果是0.346 → 0.35（不符合策略）
❌ 如果是0.234 → 0.23（不符合策略，应该向上取）
```

**修复后结果**：
```
✅ 使用 RoundingMode.UP
✅ 0.340 → 0.34
✅ 0.341 → 0.35（向上取整）
✅ 0.234 → 0.24（向上取整）
✅ 符合策略文档"向上取"的要求
```
