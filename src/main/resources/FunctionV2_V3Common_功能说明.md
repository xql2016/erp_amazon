# FunctionV2 和 FunctionV3Common 功能说明文档

## 概述

本文档详细说明了 ERP 系统中 `functionV2` 和 `functionV3Common` 两个功能模块的实现逻辑和业务规则。

---

## 一、FunctionV2 - 广告组层面控制垃圾流量

### 1.1 功能概述

**功能代码**: `function_v2`

**主要目的**: 通过降低投放入口的竞价（Bid）来控制垃圾流量，优化广告投放成本。

**核心策略**: 
- 查询昨天点击数≥1的广告组
- 根据不同广告组类型，查看近X天（可配置，默认60天）的长期数据
- 根据广告组的订单数和ACOS情况，调整投放入口的竞价

### 1.2 执行流程

#### 1.2.1 主流程（AdGroupActionV2）

1. **查询条件设置**
   - 查询昨天（report_date = 昨天）的广告组数据
   - 筛选条件：点击数 >= 1
   - 支持按国家、Hub ID、Portfolio ID 过滤

2. **广告组过滤**
   - 跳过名称为空的广告组
   - 跳过未启用（state != "enabled"）的广告组
   - 根据广告组名称识别广告组类型（关键词、ASIN、自动、类目）

3. **长期数据分析**
   - 根据不同广告组类型，从配置中获取长期天数（如"V2关键词广告组层面控制垃圾流量看的长期天数"）
   - 实际查询天数 = 配置天数 - 1（因为配置近60天实际是今天之前59天+今天）
   - 查询广告组近X天的汇总数据

4. **分发处理**
   - 根据广告组类型，调用对应的 DetailAction 处理

### 1.3 各广告组类型详细处理逻辑

#### 1.3.1 自动广告组（AutoAdGroupDetailAction）

**配置项**:
- `V2自动广告组层面控制垃圾流量看的长期天数`: 默认60天
- `V2自动广告组层面长期ACOS控制基准下限`: 默认30
- `V2自动广告组层面长期ACOS控制基准值`: 默认35

**处理逻辑**:

1. **判断是否需要处理**
   - 如果广告组近X天订单数为0 且 点击数 < 10：不处理
   - 如果广告组近X天订单数非0 且 ACOS <= 基准下限：不处理
   - 否则继续处理

2. **查询投放入口数据**
   - 查询该广告组近X天的所有投放入口数据

3. **根据广告组情况分类处理**

   **情况A：广告组无广告订单**
   
   - **点击数 10-30**:
     - 投放入口点击 >= 20：bid改为0.02
     - 投放入口点击 >= 10 且 < 20：bid = CPC + 0.08 - 0.01 * 点击数（如果当前bid > 计算值则调整）
     - 投放入口点击 >= 4 且 < 10：bid = CPC - 0.01（如果当前bid > 计算值则调整）
     - 投放入口点击 < 4：不处理
   
   - **点击数 >= 30**:
     - 投放入口点击 >= 20：bid改为0.02
     - 投放入口点击 >= 10 且 < 20：bid = CPC + 0.07 - 0.01 * 点击数（如果当前bid > 计算值则调整）
     - 投放入口点击 >= 1 且 < 10：bid = CPC - 0.02（如果当前bid > 计算值则调整）
     - 投放入口点击 < 1：不处理

   **情况B：广告组有广告订单**
   
   - **ACOS 在 (基准下限, 60] 区间**:
     - 投放入口有订单：
       - ACOS <= 基准下限：不处理
       - ACOS <= 基准值：bid = CPC（如果当前bid > CPC则调整）
       - ACOS > 基准值：bid = 基准值 * CPC / ACOS（如果当前bid > 计算值则调整）
     - 投放入口无订单：按"点击数10-30"的逻辑处理
   
   - **ACOS > 60**:
     - 投放入口有订单：同"ACOS在(基准下限, 60]区间"的逻辑
     - 投放入口无订单：按"点击数>=30"的逻辑处理

#### 1.3.2 类目广告组（CategoryAdGroupDetailAction）

**配置项**:
- `V2类目广告组层面控制垃圾流量看的长期天数`: 默认60天
- `V2类目广告组层面长期ACOS控制基准下限`: 默认30
- `V2类目广告组层面长期ACOS控制基准上限`: 默认35

**处理逻辑**: 与自动广告组完全相同

#### 1.3.3 关键词广告组（KeyAdGroupDetailAction）

**配置项**:
- `V2关键词广告组层面控制垃圾流量看的长期天数`: 默认60天
- `V2关键词广告组层面长期ACOS控制基准下限`: 默认30
- `V2关键词广告组层面长期ACOS控制基准上限`: 默认35

**处理逻辑**:

1. **判断是否需要处理**
   - 如果广告组近X天订单数为0 且 点击数 < 7：不处理
   - 如果广告组近X天订单数非0 且 ACOS <= 基准下限：不处理
   - 否则继续处理

2. **根据广告组情况分类处理**

   **情况A：广告组无广告订单**
   
   - **点击数 7-30**:
     - 投放入口点击 >= 10：关闭该投放入口
     - 投放入口点击 >= 4 且 < 10：bid = CPC + 0.04 - 0.01 * 点击数（如果当前bid > 计算值则调整）
     - 投放入口点击 >= 1 且 < 4：bid = CPC（如果当前bid > CPC则调整）
     - 投放入口点击 < 1：不处理
   
   - **点击数 >= 30**:
     - 投放入口点击 >= 10：关闭该投放入口
     - 投放入口点击 >= 4 且 < 10：bid = CPC + 0.02 - 0.01 * 点击数（如果当前bid > 计算值则调整）
     - 投放入口点击 >= 1 且 < 4：bid = CPC - 0.02（如果当前bid > 计算值则调整）
     - 投放入口点击 < 1：不处理

   **情况B：广告组有广告订单**
   
   - **ACOS 在 (基准下限, 60] 区间**:
     - 投放入口有订单：
       - ACOS <= 基准下限：不处理
       - ACOS <= 基准上限：bid = CPC（如果当前bid > CPC则调整）
       - ACOS > 基准上限：bid = 基准上限 * CPC / ACOS（如果当前bid > 计算值则调整）
     - 投放入口无订单：按"点击数7-30"的逻辑处理
   
   - **ACOS > 60**:
     - 投放入口有订单：同"ACOS在(基准下限, 60]区间"的逻辑
     - 投放入口无订单：按"点击数>=30"的逻辑处理

#### 1.3.4 ASIN广告组（AsinAdGroupDetailAction）

**配置项**:
- `V2ASIN广告组层面控制垃圾流量看的长期天数`: 默认60天
- `V2ASIN广告组层面长期ACOS控制基准下限`: 默认30
- `V2ASIN广告组层面长期ACOS控制基准上限`: 默认35

**处理逻辑**: 与关键词广告组完全相同

## 二、FunctionV3Common - 广告组层面增加有效流量

### 2.1 功能概述

**功能代码**: `function_v3_common`

**主要目的**: 通过提高广告组或投放入口的竞价（Bid）来增加有效流量，提升广告曝光和点击。

**核心策略**: 
- 查询近3天数据的所有广告组
- 根据不同广告组类型，针对曝光低、点击少的广告组，提高bid来增加流量
- 检查昨天和今天是否有变更日志，避免重复调整

### 2.2 执行流程

#### 2.2.1 主流程（AdGroupActionV3Common）

1. **查询条件设置**
   - 查询近3天（report_date = 近3天）的广告组数据
   - 支持按国家、Hub ID、Portfolio ID 过滤

2. **广告组过滤**
   - 跳过名称为空的广告组
   - 跳过未启用（state != "enabled"）的广告组
   - 根据广告组名称识别广告组类型

3. **分发处理**
   - 根据广告组类型，直接调用对应的 DetailAction 处理（不需要查询长期数据）

### 2.3 各广告组类型详细处理逻辑

#### 2.3.1 自动广告组（AutoAdGroupDetailAction）

**处理逻辑**:

1. **判断条件**
   - 如果近3天曝光 > 20：不处理
   - 否则继续处理

2. **查询近60天数据**
   - 查询该广告组近60天的汇总数据

3. **判断是否需要调整**
   - 如果近60天总点击数 >= 10：不处理
   - 如果广告组竞价 > 0.3：不处理
   - 否则：将广告组竞价调高 0.02

4. **变更日志检查**
   - 如果昨天和今天有变更日志，则不处理（避免重复调整）

#### 2.3.2 类目广告组（CategoryAdGroupDetailAction）

**处理逻辑**: 与自动广告组完全相同

#### 2.3.3 关键词广告组（KeyAdGroupDetailAction）

**处理逻辑**:

1. **查询昨天数据**
   - 查询该广告组昨天的数据

2. **判断条件**
   - 如果昨天点击 > 0：不处理
   - 否则继续处理

3. **查询前天数据**
   - 查询该广告组前天的数据

4. **判断是否需要调整**
   - 如果前天点击数 > 1：不处理
   - 如果广告组竞价 > 0.3：不处理
   - 否则：将广告组竞价调高 0.02

5. **变更日志检查**
   - 如果昨天和今天有变更日志，则不处理

#### 2.3.4 ASIN广告组（AsinAdGroupDetailAction）

**处理逻辑**:

1. **查询昨天数据**
   - 查询该广告组昨天的数据

2. **判断条件**
   - 如果昨天点击 > 0：不处理
   - 否则继续处理

3. **查询前天数据**
   - 查询该广告组前天的数据

4. **判断是否需要调整**
   - 如果前天点击数 > 1：不处理
   - 否则继续处理

5. **查询投放入口近60天数据**
   - 查询该广告组所有投放入口近60天的数据

6. **遍历投放入口处理**

   **情况A：投放入口无广告订单**
   
   - 如果投放入口点击 >= 1：不处理
   - 如果投放入口Bid > 0.3：不处理
   - 否则：将投放入口Bid增加 0.02
   
   **情况B：投放入口有广告订单**
   
   - 如果 ACOS > 40：不处理
   - 如果 30 < ACOS <= 40：打开投放入口
   - 如果 15 < ACOS <= 30：bid = CPC - 0.01（如果当前bid < 计算值则调整）
   - 如果 ACOS <= 15：bid = CPC（如果当前bid < CPC则调整）

7. **变更日志检查**
   - 如果昨天和今天有变更日志，则不处理

## 三、功能对比总结

| 对比项 | FunctionV2 | FunctionV3Common |
|--------|-----------|------------------|
| **主要目的** | 控制垃圾流量，降低bid | 增加有效流量，提高bid |
| **查询时间范围** | 昨天点击数>=1的广告组 | 近3天的所有广告组 |
| **数据查询** | 需要查询长期数据（如60天） | 直接处理或查询短期数据 |
| **处理对象** | 主要处理投放入口 | 主要处理广告组，ASIN类型也处理投放入口 |
| **调整方向** | 降低bid或关闭投放入口 | 提高bid或打开投放入口 |
| **判断依据** | 基于长期订单数、ACOS、点击数 | 基于短期曝光、点击数 |
| **变更日志检查** | 无 | 有（避免重复调整） |

- `V2关键词广告组层面长期ACOS控制基准下限`: 默认30

- `V2ASIN广告组层面控制垃圾流量看的长期天数`: 默认60
- `V2ASIN广告组层面长期ACOS控制基准下限`: 默认30
- `V2ASIN广告组层面长期ACOS控制基准上限`: 默认35
- `V2自动广告组层面控制垃圾流量看的长期天数`: 默认60
- `V2自动广告组层面长期ACOS控制基准下限`: 默认30
- `V2自动广告组层面长期ACOS控制基准值`: 默认35
- `V2类目广告组层面控制垃圾流量看的长期天数`: 默认60
- `V2类目广告组层面长期ACOS控制基准下限`: 默认30
- `V2类目广告组层面长期ACOS控制基准上限`: 默认35

### FunctionV3Common 配置项

FunctionV3Common 目前没有可配置项，使用硬编码的阈值：
- 曝光阈值：20
- 点击数阈值：10（自动/类目），1（关键词/ASIN）
- Bid阈值：0.3
- ACOS阈值：40（ASIN广告组）

## 五、注意事项

1. **FunctionV2** 主要关注长期表现，通过降低表现不佳的投放入口的bid来控制成本
2. **FunctionV3Common** 主要关注短期表现，通过提高曝光低、点击少的广告组的bid来增加流量
3. 两个功能可以同时运行，但建议根据业务需求选择合适的功能
4. 所有bid调整都会记录日志，便于追踪和审计
5. FunctionV3Common 会检查变更日志，避免在短时间内重复调整同一个广告组/投放入口

## 七、执行方式

两个功能都通过 `Processor` 类统一调度执行：

1. 在 `InputConfigurationDetail.txt` 中配置 `executeActionCodeList`，添加 `"function_v2"` 或 `"function_v3_common"`
2. 系统会根据配置自动执行对应的功能
3. 可以同时配置多个功能代码，系统会依次执行
